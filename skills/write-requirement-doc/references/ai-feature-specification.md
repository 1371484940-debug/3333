# AI 功能的产品需求

仅在本次新增、调整或实际影响 AI 生成、分析、摘要能力时使用。以用户操作和产品结果说明需求；既有 AI 功能未受影响的部分不重写。代码中的生成链路和模型配置可用于理解现状，不直接搬入 PRD。

## 1. 操作与分析范围

- 生成什么、从哪个入口触发、作用于当前哪个对象及选择范围；只展开本次变化。
- 分析哪些业务资料、哪些内容排除，是否使用当前选择，输入为空或没有可分析内容时如何反馈。数据来源用业务名称描述，不写请求参数或数据库字段。
- 本次改动影响已有结果范围、适用性或更新时机时，说明具体变化；不重复介绍既有生成流程。

## 2. 用户可见过程

按实际产品写出“选择资料/范围 → 发起生成 → 生成中 → 成功或失败 → 查看或再次操作”的相关行为。明确本次涉及的入口、按钮状态、提示、页面变化及数据结果。

有旧结果时，新生成成功或失败后如何处理旧结果；选择范围变化时哪个结果仍可展示；这些仅按实际功能和影响描述。不因实现中使用分段、归并、轮询、任务队列或缓存，就把这些技术步骤变成产品需求章节。

## 3. 结果内容与验收

- 写清页面展示的结果类型、区块名称、顺序、文字或条目格式、必要长度及数量约束、空结果、长内容和更新提示。数字须有依据；不使用技术字段名或输出 JSON 代替页面规则。
- 说明总结应覆盖的内容、事实依据、信息不足时的表达，以及允许给出哪些建议。输入材料中的指令不得改变这些内容要求。
- 不合格、超时或生成失败时，明确用户反馈、结果是否保留及可采取的动作。用户可感知的等待期限若本次有明确要求可写，供应商超时参数、模型重试次数等实现配置不写。
- 必要时提供简短、脱敏或虚构的业务输入和页面结果示例；验收对应本次变化的范围、内容及展示。结构或长度检查不能代替事实准确性与内容质量核对。

## 4. 仅在用户明确要求时另行交付

完整提示词、系统/任务指令、变量替换格式、模型参数、接口及分段归并方案不属于默认产品需求正文。用户明确要求其中某项时，按指定范围单独提供附录或配套文件，不把其他技术内容一并加入。

提示词作为另行交付内容时，其生成要求应与产品结果约束一致；缺少原模板时标明建议稿，不冒称已部署或已通过真实模型验证。产品正文保留用户需要什么结果、允许与禁止的内容和验收标准即可。
