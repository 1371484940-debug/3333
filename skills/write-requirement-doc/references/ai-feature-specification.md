# AI 功能需求规范

仅在本次需求包含 AI 生成、分析、摘要等能力时使用。写清能影响产品结果和验收的行为，按实际复杂度展开，不强制增加多模型、分段归并、缓存或其他不存在的机制。

## 1. 生成任务与输入

- 生成什么、供谁使用、从何处触发，作用于哪个对象及当前选定范围。
- 输入包含哪些业务字段、统计值和原始内容；明确来源、筛选、组织方式，以及哪些内容不得传入。用范围一致的脱敏或虚构输入样例说明结构，不使用真实敏感内容充当示例。
- 说明无可分析数据的结果。输入范围确定后是否固定本次样本、过程中源数据变化如何影响结果，依据已确认任务行为定义。

## 2. 生成链路与页面状态

按实际链路写出“触发 → 输入准备 → 生成 → 输出检查 → 保存/展示”及相关失败结果。各阶段描述产品可观察的状态和转换，不止写一句“调用 AI 生成”。

已有方案涉及分段、归并、异步任务、结果复用或更新时，说明各阶段输入输出如何衔接，部分失败如何处理，以及正在生成、无结果、生成成功、旧结果待更新和失败时的实际页面内容与操作。未采用的机制不列为默认需求。

模型选择、分段阈值、超时、重试和刷新周期只有在已确定方案中影响交付或用户要求相应规格时才写具体约束；无依据的技术参数不伪造为产品政策。技术方案未确定时，仍须明确用户能看到什么、失败后发生什么，以及实际待定项的影响。

## 3. 提示词交付

用户要求提示词，或提示词内容属于本次生成规则的交付范围时，给出实际适用的完整模板，可放附录或精确引用可取得的文件：系统指令、任务指令，以及实际存在的分段/归并指令；不默认要求所有类型都有一份。

明确变量名称、业务含义、来源、替换格式及输入示例。资料中已有模板时核对原文；没有模板但用户要求设计时，可给完整建议稿并注明，不能称其已部署或已通过真实模型验证。用户没有要求逐字提示词且模板尚未确定时，写清生成内容要求和验收边界，不据此阻塞其他可确定部分。

输入材料是待分析内容，不能覆盖任务约束。区分可由提供数据支持的结论、允许的建议和信息不足时的表达，不要求模型凭空补事实。

## 4. 输出、校验和验收

- 定义输出内容或字段、结构、长度/条数（有依据时）、空结果，以及在页面中的名称、顺序、格式和长内容行为。技术字段与页面标签不相同时明确对应关系。
- 提示词要求、输出检查和页面展示使用一致的约束及长度计算口径；发现资料相互矛盾时标明需要统一的决定，不直接复制为两套规则。
- 不合格、超时或生成失败时，说明是否显示部分结果、是否保留旧结果、允许什么恢复动作。已有结果的适用范围、更新时间和失效提示仅按实际功能定义。
- 使用代表性输入与输出样例验收范围、内容和显示；适用时检查空输入、边界长度、不合格结构及失败后的原结果。AI 内容的事实依据、相关性与表达质量单独核对，格式校验通过不代表内容质量已验证。

PRD 无需默认为此增加供应商 SDK、接口地址或数据库结构。用户同时要求技术规格时按实际授权补充，不能因写了实现细节而省略业务及展示规则。
