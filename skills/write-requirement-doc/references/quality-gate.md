# 交付检查与验收

完整需求、详细功能说明及需求审查使用本检查；局部修订按变更范围和关联影响检查。内部复核无需逐项向用户播报，也不引入新的审批阶段。

## 1. 覆盖检查：每个功能是否真正展开

对照工作清单，为每个页面/区块/动作找到规则位置或明确缺口：

- 原型/需求中的页面、页签、区块、弹窗、抽屉和子页面是否都有说明？是否仅写了区块名称？
- 每个字段和固定枚举能否找到定义？动态选项的来源和范围是否明确？
- 每个实际操作是否有触发、条件、处理、结果及适用失败行为？流程分支是否遗漏？
- 关联模块的变化是否有落点，引用是否真的指向对应规则？

不得通过自行删除难写区块、编造默认值或把所有缺口都塞进文末使覆盖表看似完成。

## 2. 可执行检查：同样输入能否得出确定结果

从开发和测试视角核对，而不是检查是否出现了“权限”“异常”等词：

| 检查对象 | 判定问题 |
|---|---|
| 条件 | 哪些条件同时满足或任选其一？临界值是否包含？数据变化后用哪个时点判断？ |
| 展示 | 能否确定各区块、字段、文案、顺序、格式、点击行为及适用页面状态？ |
| 输入 | 能否确定完整选项、范围、必填、联动、校验及错误处理？ |
| 状态 | 给定当前状态和事件，能否确定成功流转或拒绝及其结果？ |
| 权限 | 能否分别判断可见、可操作、数据范围和执行时的拒绝结果？ |
| 数据 | 成功改变什么、保留什么，失败是否留下部分结果，关联数据是否变化？ |
| 统计 | 用同一小样本是否能算出唯一结果，并解释零分母和时间边界？ |
| 恢复 | 失败后界面与输入处于什么状态，用户如何重试或确认结果？ |

将“支持筛选”“校验通过后保存”“按权限展示”“记录变更动态”“异常时提示”等句子作为定位线索；只有其缺少具体定义或精确引用时才判为缺口，不靠关键词命中自动判错。

## 3. 一致性与范围检查

- 术语、必填字段、枚举、状态、按钮条件、权限范围在正文、表格、示例和验收中是否一致？
- 当前值与历史事实、业务状态与展示标签、计划金额与实际金额是否被混用？
- 流程图中的转换、正文中的校验、状态表中的结果能否互相对应？
- 正常空值与违反业务约束的数据异常是否区分？没有数据与读取失败是否被混写？
- 用户最后一次修正是否同步到相关章节、文案、验收和关联文档？用户已明确排除的概念是否仍残留于业务规则或示例？
- 原型未体现的业务规则是否有依据或标明待确认？是否仅凭演示数据、模板例子或历史项目设定扩大范围？
- 文档描述的是产品结果，还是未经要求指定了代码、接口、数据库和框架？

## 4. 规则与验收对应

关键规则使用稳定章节＋条款号或规则 ID。场景不必与段落一一对应，但应能追踪回规则；同一场景可以验证多个相关规则。无需为每句文案生成测试用例。

| 场景编号 | 对应规则 | 前置条件与输入 | 操作/事件 | 预期页面结果 | 预期数据及关联结果 |
|---|---|---|---|---|---|
| AC-01 | 具体规则位置 | 角色、状态和必要边界值 | 明确动作 | 可观察的展示、反馈、刷新 | 新增/变更/不变或不适用 |

按风险与适用性覆盖：正常完成、无权限/条件不满足、临界值、状态变化、空/失败以及会影响结果的组合。例如字段合法但状态已变化、部分记录可操作的批量请求。避免对所有角色×状态×字段做无意义全排列。

复杂正文需要展示样例；计算需要具体输入和验算结果；状态操作需要成功与拒绝结果。验收不能只写“符合规则”“保存成功”或只检查提示而忽略数据。

## 5. 待确认事项与完成判断

| 编号 | 缺失决定或冲突 | 已知依据/建议（明确区分） | 影响规则 | 阻塞的开发或验收范围 | 可独立推进部分 |
|---|---|---|---|---|---|
| Q-01 | 写成可回答的问题 | 不把建议当确认 | 指向具体条款 | 说明实际影响 | 列出不依赖此决定的部分 |

待确认表只收录实际需要决定或存在关键依据缺口的事项。任务授权内合理补充的普通展示文案、布局、加载样式等集中标明建议，不单独造成“不可开发”结论；按建议实现的部分可列明建议下的预期表现，不冒称业务已确认。用户明确要求先确认该项时仍保留确认边界。

根据事实区分交付状态：

- **可开发验收**：当前范围关键行为有明确依据和规则，适用检查通过，无影响该范围实施的关键待定项。
- **部分可开发验收**：有具体待定项，明确哪些部分可推进、哪些需等决定；不把待定部分写成唯一行为。
- **待确认草稿**：核心流程、权限或计算口径仍未确定；交付已完成内容和聚焦问题，不宣称完整。

这些状态用于诚实表达交付成熟度，不要求每篇文档增加固定状态页或等待用户批准。

修复自己能够依据现有资料解决的缺口后再交付。自查不等于已经由研发、测试或业务实际评审，未做的验证不得宣称完成。
