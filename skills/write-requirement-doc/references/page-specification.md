# 页面与区块详细规范

用于所有含页面的需求，包括后台列表、详情、编辑表单、展示页及子界面。目的是定义能被实现和验收的产品行为，不要求逐像素重写视觉设计。

## 1. 先盘点，再展开

从实际资料识别页面入口、适用端、页签、区块、主要状态、操作入口及弹窗/抽屉/二级页面。原型有可操作状态时，检查相关切换和打开结果；只有截图时，区分可见事实与未体现行为。

页面概述写打开条件、标题/副标题、主体区块顺序、固定操作区及关闭/返回行为。每个实际区块应有对应小节或可定位条款。区块包含复杂子结构时继续拆分，不能只详细写最复杂的一个。

## 2. 每个区块的最低说明范围

按适用性覆盖以下内容；不适用的项无需生成占位段落：

| 维度 | 要回答的问题 |
|---|---|
| 位置与作用 | 在页面哪里，区块名称是什么，以什么结构承载信息？ |
| 展示条件 | 哪些页面状态、业务状态、用户条件下展示？无数据时隐藏还是显示空态？ |
| 数据范围 | 展示当前对象的哪些数据，包含和排除哪些状态，是否受其他筛选影响？ |
| 字段与来源 | 每项取自哪个业务对象，是当前值、历史事实还是计算结果？ |
| 展示格式 | 标签、单位、日期精度、金额精度、正文顺序、长文本处理如何确定？ |
| 数据组织 | 默认顺序、同值处理、数量限制、分页/加载方式是什么？ |
| 交互 | 哪个具体元素可点击、可编辑、可展开？触发后去哪里或发生什么？ |
| 操作结果 | 成功或失败后，当前区块、其他区块、列表及关联对象如何变化？ |
| 页面状态 | 加载中、正常无数据、读取失败、无权限分别怎样呈现及恢复？ |

正常可空字段可以定义空值文案。按业务约束必定存在的数据，异常缺失不应自动设计成正常空态；说明异常处理范围和用户可采取的动作。不要把“未知客户”“编号待补充”等占位词当成通用兜底。

## 3. 常见区块的展开重点

### 列表、卡片和摘要

- 定义每列或卡片每个位置的字段、标签、格式及来源，区分计划值、实际值、剩余值等相近概念。
- 默认排序包含方向和同值处理；使用状态优先级时完整列出。采用分页时写明默认页容量、可选值、筛选或页容量变化后的页码行为；选择不分页也须明确，不自行假设。
- 说明整行、名称、操作按钮分别是否可点击，避免“可查看”被误解为“可打开独立详情”。
- 若支持选择或批量操作，说明选择范围、跨页保留、全选含义、不可选项及成功失败后选择状态。
- 卡片简化业务状态时，给出完整业务状态到展示标签的映射；排序、统计使用哪套状态分别说明。

### 筛选、搜索和页签

- 每个条件说明控件、选项、默认值、匹配字段和方式；多条件之间以及多选值之间的“且/或”关系明确。
- 区分切换即生效、点击查询或其他触发方式。说明重置后的值、页码和结果范围。
- 日期筛选明确业务时间字段、边界和适用时区；不把“最近一个月”等模糊区间直接交付。
- 页签说明名称、出现条件、数据范围、默认项和切换后的筛选/分页保留规则；数字徽标若存在，写清统计口径和刷新时机。

### 表单、弹窗和抽屉

- 写清打开入口、标题、字段顺序、回填来源、可编辑条件和自动关联的数据。字段规则按 [业务规则](business-rules.md) 展开。
- 定义各按钮的名称、可用条件、点击后校验和处理；按钮是否展示、是否可点、业务是否允许执行分开描述。
- 说明保存、取消、关闭、返回等实际存在入口的结果；涉及未保存输入时，明确丢弃、保留或确认行为，不默认添加自动保存。
- 成功后说明是否关闭、返回位置、列表或区块刷新及排序变化；失败时说明是否保持打开、输入保留和重试。提交期间说明重复触发的页面行为及业务结果。

### 动态、时间线、通知和其他结构化正文

- 在当前范围内完整列举类型，不写“审批、变更等”。类型较多可使用引用到完整定义的事件表。
- 每种类型定义产生条件、标题、必需业务内容、实际操作主体和时间来源，区分业务事实与展示文案。
- 写清单条内容结构、信息顺序、正文模板及代表性展示示例；涉及修改时说明前后值、多字段顺序和无变更行为。
- 明确长内容换行/截断/展开方式、排序、数量/分页、空值、点击或链接行为。图标与颜色仅在原型或设计约定存在且影响理解时说明，不凭空规定装饰细节。
- 说明哪些业务操作成功后产生记录，哪些失败或取消不产生记录；一次操作产生多条记录时定义顺序与去重语义。不要把“不可修改”当成所有类型记录的默认业务规则。

### 文件、附件、图表和其他专用区块

- 文件区分上传允许格式、历史文件展示、预览和下载能力；明确相关权限、文件大小、数量及替换后影响，数字未知则标明待确认或建议。
- 图表明确指标口径、维度、单位、图例/悬浮信息及点击筛选或跳转（实际存在时）；计算规则引用具体指标定义。
- 专用控件按其真实交互补充规则，不从通用模板引入无关能力。

## 4. 页面之间与状态之间的连接

同一详情从不同入口进入时，说明复用关系及实际差异。是否允许查看依据明确的业务权限；入口路径只有在产品明确规定差异时才成为限制，不能随意增加绕行规则。

关联对象变更后，定义刷新触发点、要重新读取的当前信息与应保留的历史事实。权限或业务状态在操作期间变化时，说明重新判断及拒绝结果。当前页有未保存输入时，不以笼统“立即刷新”覆盖输入处理规则。

引用其他文档只复用公共业务口径；当前页面仍需交代显示什么、显示在哪里、哪些元素可操作及操作后的页面行为。
