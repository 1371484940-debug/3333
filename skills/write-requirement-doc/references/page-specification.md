# 页面与区块详细规范

用于所有含页面的需求，包括后台列表、详情、编辑表单、展示页及子界面。目的是定义能被实现和验收的产品行为，不要求逐像素重写视觉设计。

## 1. 先盘点，再展开

从实际资料识别页面入口、适用端、页签、区块、主要状态、操作入口及弹窗/抽屉/二级页面。原型有可操作状态时，检查相关切换和打开结果；只有截图时，区分可见事实与未体现行为。

先列本次新增、调整及实际受影响的内容，再按页面组织；一页只是新增一个控件时，详细写这个控件及它改变的既有行为，不重新介绍整页。必要上下文用一句定位或精确引用表达，不逐项列出旧功能“不变”。每个改动元素展开到具体取值、条件、动作和结果；没有意义的重复拆段、技术实现细节和像素级描述不属于最小颗粒度。

以下维度是检查已有功能的工具，不是新增功能清单。原型和明确需求未包含的内容不主动写入；只有发现现有原型的具体问题或必要缺口，才补最小修正规则并说明依据。普通呈现沿用项目约定，不能为追求“完整”堆入多余提示和极端情形。

新页面或用户要求的全量页面说明，写打开条件、标题/副标题、主体区块顺序、固定操作区及关闭/返回行为。既有页面的增量需求只写本次位置及变化，打开条件、标题和其他区块未受影响时不重述。复杂的新增或改动区块继续拆分，不能只详细写其中一个。

盘点区块时同时读取其可见文字：标题、副标题、辅助说明、字段标签、输入占位、字段旁说明、状态标签及配套说明、操作确认与结果提示、空态。实际存在或已确定需要的内容逐项覆盖；这份清单不要求给每个区块新增所有文案类型。仅检查默认状态不足以覆盖条件文案，需结合资料中的实际状态或交互核对；看不到的部分区分建议与未确认事实。

### 原型与文档对照

1. **确定同一版本。** 记录本次采用的原型链接或文件、页面/画板定位，以及可取得的版本或查看时间。用户未指定且存在相互冲突的版本时先查已确认记录，不静默任选；可继续处理不受冲突影响的页面。不要把源码中的新文案当作当前运行页面已经展示的内容。
2. **按本次范围实际查看。** 可交互原型需打开相关页面、切换实际存在的页签和状态、查看弹窗和操作反馈；仅看默认首屏或读组件名称不足以推导这些行为。在原型或隔离数据中验证，不为编写文档执行真实生产业务操作。只有静态图或受限访问时，标明哪些交互未验证，沿用已确认规则，不以惯例补成“原型如此”。
3. **逐元素记录。** 核对字段与按钮名称、区块顺序、辅助文字、实际选项和默认值、状态标签及说明、提示方式、出现位置、是否可点、打开弹窗或页面跳转、操作后停留/返回/刷新。只核对当前范围内实际相关项，不为此新增原型没有的控件和分支。
4. **保留真实差异。** 同一个名称在不同入口或状态下可能表现不同，分别记录本页行为；不要自动把抽屉写成独立页面、把点击写成悬停、把置灰写成完全不可点，或把两个不同字段改成同一术语。需要修正原型时按具体问题说明，不用“统一体验”掩盖未经授权的改动。
5. **区分现状与修正。** 对确实有问题的原型，简明记录“原型位置及现状 → 与已确认规则的冲突或必要缺口 → 本文采用的修正规则及其依据”。没有充分依据的业务决定保持待确认；不把修正后的预期冒称已在原型实现。不重复记录已放弃方案。
6. **写后再对照。** 从原型检查文档有没有漏写，再从文档检查有没有改写或凭空添加。字段表、操作表、正文、文案示例和验收同时核对；原型后续改变时更新相关位置。已复核且依据未变的部分不反复查看，变更部分及时重新核对。

对照可复用工作清单，增加 `页面/状态/入口｜原型证据位置｜对应文档条款｜已核对/差异/未验证`。详细对照记录用于内部检查；正文只保留必要规则及实际差异，避免附加大段验证过程。无法取得原型时如实说明受限范围，不将推测包装为已验证的页面描述。

## 2. 每个区块的最低说明范围

以下维度只用于本次新增、调整及受影响的元素；不适用的项和未变化的旧规则无需生成段落。精确引用足以说明必要前提时不重复展开：

| 维度 | 要回答的问题 |
|---|---|
| 位置与作用 | 在页面哪里，区块名称是什么，以什么结构承载信息？ |
| 展示条件 | 哪些页面状态、业务状态、用户条件下展示？无数据时隐藏还是显示空态？ |
| 数据范围 | 展示当前对象的哪些数据，包含和排除哪些状态，是否受其他筛选影响？ |
| 字段与来源 | 每项取自哪个业务对象，是当前值、历史事实还是计算结果？ |
| 页面文案 | 哪些文字固定，哪些含变量或随条件变化；其原文/模板、所在位置与出现条件是什么？ |
| 展示格式 | 标签、单位、日期精度、金额精度、正文顺序、长文本处理如何确定？ |
| 数据组织 | 默认顺序、同值处理、数量限制、分页/加载方式是什么？ |
| 交互 | 哪个具体元素可点击、可编辑、可展开？触发后去哪里或发生什么？ |
| 操作结果 | 成功或失败后，当前区块、其他区块、列表及关联对象如何变化？ |
| 页面状态 | 加载中、正常无数据、读取失败、无权限分别怎样呈现及恢复？ |

正常可空字段可以定义空值文案。按业务约束必定存在的数据，异常缺失不应自动设计成正常空态；说明异常处理范围和用户可采取的动作。不要把“未知客户”“编号待补充”等占位词当成通用兜底。

## 3. 常见区块的展开重点

### 辅助文案、字段提示与操作反馈

- 明确文字的用途和载体：页面用途说明、字段标签、输入占位、字段帮助、状态解释和操作反馈不能互相替代。表单的字段提示不是字段值，业务解释也不自动成为页面辅助文字。
- 已确认的固定文案记录原文或引用明确的公共文案条目；原型已有提示入口却缺少必要表达时，优先沿用项目文案，无可复用表达才补具体文案并说明依据，不只写“合理提示”。不为原型中不存在且非必要的提示另造文案。公共规则可复用，不必每页抄写。
- 动态文案给出完整模板、变量来源、格式及正常缺失时的处理，配一条能看懂的实际值示例；按业务要求必定存在的值异常缺失，依数据异常规则处理，不随意补正常占位。文案中的“如有”“根据情况”应能追溯到明确条件。
- 随状态变化的辅助说明与标签一起定义。两个状态使用同一说明也应明确覆盖这两个状态，不能因文字相同而漏掉一个分支。
- 已有交互提示应写清：入口和触发动作、出现条件、承载形式与位置、文案/模板、适用的持续或关闭方式，以及触发后的页面、输入与数据结果。精确时长等沿用现有组件或设计规范；只有不明确会影响当前行为时才补齐，不沿用其他项目数字。
- 分别描述入口外观、可接受的交互和业务动作是否执行。不能从“置灰”自行推导为完全无法点击，也不能假定点击或悬停必定提示；按该产品已确定行为写清。这里只规定文档应描述的行为，不以文案写作代替实现问题排查。
- 辅助文案沿用同系统同类页面的表达和术语；帮助用户理解当前内容、限制或下一步即可。避免重复已有标题/数量、讲述改造过程或添加内部实现解释。删减非必要页面提示时，仍在文档中保留必要业务约束。

可按实际复杂度使用以下表格，不要求每个提示都单独建表：

| 位置/载体 | 展示条件或触发动作 | 文案原文/模板 | 变量来源与格式 | 关闭方式及页面结果 |
|---|---|---|---|---|
| 页面实际元素 | 明确出现时点 | 固定文字或完整动态表达 | 固定文字可不填此列 | 常驻说明与交互反馈分别说明 |

### 状态标签、状态说明与联动展示

- 为“当前状态”等字段命名时说明所属业务对象，区分主体、某次任务、明细和生成结果等不同对象的状态，不额外创造原业务没有的状态或原因字段。
- 写清完整取值及展示条件，关联同一套业务状态定义；同时定义标签、状态下方说明、组合格式和相关元素的显示/可用情况。业务状态表已有定义时可精确引用，但不能省略当前页面配套文字。
- 只有真实存在的独立信息才单列字段。状态标签、状态说明和原因是否分开，应根据最终产品方案确定，不能因为底层有字段就全部展示，也不能把用户已去除的字段作为“可选项”保留。
- 条件变化时说明哪些标签、说明、按钮或其他元素联动更新，以及更新触发方式。涉及时刻边界时与业务时区、端点和取时依据一致；不要默认所有状态都实时轮询。

| 状态所属对象及取值 | 判定条件或规则引用 | 标签原文 | 配套说明原文/模板 | 相关元素展示与更新 |
|---|---|---|---|---|
| 当前页面实际对象 | 可判断的条件 | 用户看到的名称 | 无说明时明确按设计不设说明 | 只列实际关联元素 |

### 列表、卡片和摘要

新增一个筛选、字段或入口，不代表列表排序、所有列、分页、其他按钮都要重写。只描述本次增量及其对列表结果、页码、选择、导出等已确认的实际影响；新增整张列表时才展开完整列表规则。

- 定义每列或卡片每个位置的字段、标签、格式及来源，区分计划值、实际值、剩余值等相近概念。
- 默认排序包含方向和同值处理；使用状态优先级时完整列出。采用分页时写明默认页容量、可选值、筛选或页容量变化后的页码行为；选择不分页也须明确，不自行假设。
- 说明整行、名称、操作按钮分别是否可点击，避免“可查看”被误解为“可打开独立详情”。
- 若支持选择或批量操作，说明选择范围、跨页保留、全选含义、不可选项及成功失败后选择状态。
- 卡片简化业务状态时，给出完整业务状态到展示标签的映射；排序、统计使用哪套状态分别说明。

### 筛选、搜索和页签

- 每个条件说明控件、选项、默认值、匹配字段和方式；多条件之间以及多选值之间的“且/或”关系明确。
- 区分切换即生效、点击查询或其他触发方式。说明重置后的值、页码和结果范围。
- 日期筛选明确业务时间字段、边界和适用时区；不把“最近一个月”等模糊区间直接交付。
- 页签说明名称、出现条件、数据范围、默认项和切换后的筛选/分页保留规则；数字徽标若存在，写清统计口径和刷新时机。

### 表单、弹窗和抽屉

- 写清打开入口、标题、字段顺序、回填来源、可编辑条件和自动关联的数据。字段规则按 [业务规则](business-rules.md) 展开。
- 定义各按钮的名称、可用条件、点击后校验和处理；按钮是否展示、是否可点、业务是否允许执行分开描述。
- 说明保存、取消、关闭、返回等实际存在入口的结果；涉及未保存输入时，明确丢弃、保留或确认行为，不默认添加自动保存。
- 成功后说明是否关闭、返回位置、列表或区块刷新及排序变化；失败时说明是否保持打开、输入保留和重试。提交期间说明重复触发的页面行为及业务结果。

### 动态、时间线、通知和其他结构化正文

- 在当前范围内完整列举类型，不写“审批、变更等”。类型较多可使用引用到完整定义的事件表。
- 每种类型定义产生条件、标题、必需业务内容、实际操作主体和时间来源，区分业务事实与展示文案。
- 写清单条内容结构、信息顺序、正文模板及代表性展示示例；涉及修改时说明前后值、多字段顺序和无变更行为。
- 明确长内容换行/截断/展开方式、排序、数量/分页、空值、点击或链接行为。图标与颜色仅在原型或设计约定存在且影响理解时说明，不凭空规定装饰细节。
- 说明哪些业务操作成功后产生记录，哪些失败或取消不产生记录；一次操作产生多条记录时定义顺序与去重语义。不要把“不可修改”当成所有类型记录的默认业务规则。

### 文件、附件、图表和其他专用区块

- 文件区分上传允许格式、历史文件展示、预览和下载能力；明确相关权限、文件大小、数量及替换后影响，数字未知则标明待确认或建议。
- 图表明确指标口径、维度、单位、图例/悬浮信息及点击筛选或跳转（实际存在时）；计算规则引用具体指标定义。
- 专用控件按其真实交互补充规则，不从通用模板引入无关能力。

## 4. 页面之间与状态之间的连接

同一详情从不同入口进入时，说明复用关系及实际差异。是否允许查看依据明确的业务权限；入口路径只有在产品明确规定差异时才成为限制，不能随意增加绕行规则。

关联对象变更后，定义刷新触发点、要重新读取的当前信息与应保留的历史事实。权限或业务状态在操作期间变化时，说明重新判断及拒绝结果。当前页有未保存输入时，不以笼统“立即刷新”覆盖输入处理规则。

引用其他文档只复用公共业务口径；当前页面仍需交代显示什么、显示在哪里、哪些元素可操作及操作后的页面行为。

上句所指为本次新增、调整或受影响的页面表现，不要求复述已有页面全部行为。读取源码时将数据来源描述为业务对象或业务计算，不写表名、接口参数、组件名或请求流程；后台机制的细节无需进入页面需求。
