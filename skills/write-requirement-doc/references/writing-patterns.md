# 按需求类型选择写法

以下六类对应用户模板的范例分类，补充开发测试需要判断的条件与结果。先按 `SKILL.md` 确定范围，再只读适用章节；这些维度不是功能清单。示例中明确给出的事实仅在该示例成立。

## 目录

1. 字段增加或调整
2. 流程型需求
3. 多状态及不同处理
4. 列表管理：查询、卡片、表单、操作、权限
5. 数据统计
6. 页面展示
7. 原有规则与关联影响的写法

## 1. 字段增加或调整

适用于局部字段或文案变化。先说明涉及页面及适用状态，再按页面位置描述新增或调整项。原模板的“作业基本信息展示”只列受影响提交页面与新增内容，未重写作业提交功能。

- **展示字段：** 写位置、名称、数据来源、展示条件和必要格式；可正常为空时说明空值显示。数据缺失违反业务规则时，不随意设计成正常占位。
- **输入字段：** 按需写类型、长度/范围、必填条件、默认/回填、完整选项或选项来源、联动及可编辑条件。文件输入涉及格式、大小和数量时明确限制；日期、数字和百分比按项目口径说明精度与单位。
- **校验：** 写比较范围、边界及提交时的反馈；唯一性应能确定在哪些记录中比较。没有依据的长度和默认值不能从模板例子抄入。
- **影响：** 只补该字段在其他页面、已有记录或输出中实际发生的变化。多个位置共用口径时定义一次。

多字段可采用：`字段名称｜类型/长度｜必填条件｜默认值/来源｜约束及反馈`。单字段几条规则即可。

**局部示例。** 给定：工单新增“服务等级”，单选标准/加急，必选，默认标准；创建、编辑位于名称下方，旧记录显示标准；列表和既有导出均在名称后增加该值。

合适的写法分别落在创建/编辑字段、列表新增列、导出新增列，并说明旧记录显示标准。只写“增加服务等级”会漏规则；重列全部旧字段、分页和下载流程会扩大正文。如何修改数据库不进入本需求。

## 2. 流程型需求

按业务发生顺序说明角色、起点、实际分支及结束结果。流程复杂时先给流程图，详细规则落在对应入口；同一个分支不要在图、表和正文中各定义一套条件。

每个本次操作说明：

1. 谁从哪里触发，对哪个对象或范围操作；必要前置条件是什么。
2. 需要输入什么，先后执行哪些会影响反馈的校验。
3. 成功时对象如何变化，页面停留、关闭、跳转还是刷新。
4. 实际存在的取消、拒绝和失败分支各是什么结果；原数据、输入如何处理，如何再次操作。

原模板的消息订阅例子分别写成功、取消、拒绝后的去向及下次是否再提醒，体现分支结果的区别。其他需求不因此新增订阅、通知、取消或重提能力。

涉及多人操作导致条件变化时，说明以哪个时点判定及拒绝后的业务结果。只有流程确实需要时才写时限、超时、撤回、重提和通知，不按通用流程模型补齐一套能力。

## 3. 多状态及不同处理

先说明状态属于哪个业务对象，并区分业务状态和仅用于页面显示的标签。只列当前范围真实存在的状态；枚举完整，条件可判断。

有多个入口时可用：`页面/入口｜对象状态及条件｜展示内容或提示｜可执行动作｜执行结果`。多个条件共同决定行为时说明“同时满足”或“任一满足”，避免使用未定义的“符合分类”。

检查重点：

- 状态标签、配套说明及相关按钮使用同一判定；有动态提示时给文案模板及变量含义。
- 操作执行条件与入口外观分别写明；置灰是否仍可点击查看原因，以实际设计为准。
- 状态变化后何时更新页面，哪些历史信息保留；只有本次真实涉及时才写恢复规则。

**局部示例。** 给定某文件结果面板显示当前处理任务状态，状态下有说明；收到任务更新后刷新；仅可下载状态显示下载按钮。

| 任务状态 | 标签 | 说明原文 | 下载按钮 |
|---|---|---|---|
| 处理中 | 处理中 | 文件准备中，请稍候 | 隐藏 |
| 可下载 | 可下载 | 文件已准备完成 | 显示 |
| 失败 | 失败 | 文件准备失败，请重新生成 | 隐藏 |

这样可以核对标签、文字和入口是否一起变化；不能只写“展示当前状态及相关提示”。重新生成若已有规则，引用其位置，不因示例文案而发明新的操作流程。

## 4. 列表管理

本类包含列表、卡片、查询、表单、弹窗和实际提供的操作。只改一个筛选或按钮时，选用该部分；新增完整页面时再组合展开整页。

### 4.1 查询和页签

说明位置、名称、控件、选项/来源、默认条件、匹配对象与方式、触发生效方式、重置结果，以及与其他条件的且/或关系。页签还要说明各自结果范围。页码、选择状态、计数、导出仅在受影响时补相应结果。

多条件可用原模板的列式：`查询字段｜输入类型｜查询方式｜默认条件｜约束说明`。选项与触发方式写在对应约束中，不必再复制一张表。

**局部示例。** 给定资料列表已有分类筛选与查询、重置按钮；本次在分类右侧新增“归档状态”，单选全部/未归档/已归档，默认未归档；点击查询生效，与分类取交集；重置回到未归档；查询或重置后回到第一页。

正文据此写这一查询项及结果变化即可。“支持按归档状态筛选”缺少选项和触发规则；展开列表全部旧按钮、排序和页容量也无必要。

### 4.2 列表和卡片展示

- 新增或变化的字段/标签写明位置、来源和格式。名称、整行及操作图标是否可点击分别说明。
- 操作区说明图标位置、显示条件和点击行为。存在互斥或优先关系时给出可判定条件；是否隐藏或置灰采用项目实际设计。
- 新增列表需要明确排序方向、同值处理、分页或加载方式；旧列表仅在这些规则变化时展开。
- 实际支持选择或批量操作时，说明选择对象、范围及执行结果；不因模板含批量删除就增加该功能。

### 4.3 新增、编辑表单及弹窗

按“打开入口 → 页面内容 → 按钮 → 校验 → 结果”展开：

1. 入口、标题、字段顺序、默认或回填及可修改条件。字段约束用第 1 节的写法。
2. 按钮名称与可用条件。存在确认弹窗时写标题、正文、动态变量及按钮，不只写“弹窗确认”。
3. 提交判断与失败提示；同次可能出现多种错误时，若先后影响用户反馈则说明顺序。
4. 成功后的状态/数据变化，以及关闭、返回、列表刷新结果；失败后弹窗和输入怎样处理。
5. 实际存在的取消、关闭和返回入口如何处理未提交输入。重复提交、部分成功等只有会影响当前业务结果时再定义。

编辑与新增相同的约束引用具体章节，只展开回填、不可修改项及提交差异。这与原模板“编辑量表”的处理一致；引用不能掩盖尚未定义的差异。

### 4.4 操作及删除

先核实本次操作改变哪项条件或结果。新建操作须说明执行资格、输入、校验、确认、成功与拒绝；已有操作只说明变化。

- 必要的引用或使用限制写明判定对象及范围，不能以“已使用”“有引用”代替关键定义。
- 若只增加所属对象的状态限制，采用第 7 节的简短写法，原删除条件不重新展开。
- 实际改动批量处理时，说明逐项资格、全部成功或允许部分成功、结果反馈及未完成项；不凭惯例选择整批回滚或逐项成功。
- 涉及关联数据变化时明确哪些结果应同时成立、失败后保留什么；不指定事务、锁等实现机制。

### 4.5 权限及功能配置

本次新增配置项时，写清所在页面和位置、准确名称、控制的动作、默认值或既有角色的处理、保存及生效方式。涉及多个动作时明确是否共用同一项。

区分菜单可访问、内容可见、动作可执行和数据范围。根据本次变化写无权限时的展示及执行结果；只有使用中变化影响操作时才补重新判断。仅使用已有权限且未改变含义时，引用具体权限即可，不重写整张权限矩阵。

## 5. 数据统计

原模板依次写展示、统计范围及公式、排序。沿此顺序说明本次指标：

- **展示：** 页面位置、指标名、维度、单位及实际有的图表/点击行为。
- **口径：** 统计对象、时间与状态范围、计数单位、去重和排除条件；涉及时间端点时明确是否包含。
- **计算：** 分子、分母或聚合公式、精度及舍入时机；区分平均各次比例与汇总人数后的比例。
- **边界与变化：** 无数据、零分母如何显示；取当前数据还是某时点数据，后续更正是否影响已有结果。只写本次确实涉及的行为。
- **排序：** 排序方向及并列处理，适用时说明取前几项。

**验算示例。** 给定参与集合为甲、乙、丙，有效签到按人去重且排除集合外人员；甲签到两次，丁签到一次，其余未签到。参与人数为 1，应参与人数为 3。若约定四舍五入保留一位小数，则为 33.3%。零分母显示什么须来自项目规则，不沿用本例臆定。

## 6. 页面展示

按页面布局逐区块说明本次新增或调整的内容。原模板的 banner、新闻、通知及导师区块均围绕数据来源、排序、展示内容和点击去向编写。

按实际区块选择：

- 数据来自哪个业务对象、范围是什么、展示多少条及排序依据。
- 每条显示哪些内容、顺序与必要格式，正常为空或缺图时如何处理。
- 标题、辅助说明、字段提示、状态说明和反馈文案；动态文案说明变量来源。可见文字与业务字段都要核对，不把内部解释全部展示给用户。
- 点击、悬停、展开等真实存在的动作与结果。只有长内容确实需要处理时写截断、换行或展开方式。
- 新增或受影响的空态、加载和失败如何表现；已有公共表现可引用项目规范，不为每个区块新建一套异常处理。

时间线、通知等结构化正文，在本次涉及时列出实际类型、产生条件、标题/正文结构、主体和时间，以及点击去向。使用当前值还是历史事实须依据业务说明，不能仅写“展示操作记录等”。

## 7. 原有规则与关联影响的写法

### 仅增加前置限制

给定某题库新增归档状态，归档后禁止删除题目和导入，恢复后按原规则操作。局部条款可写：

1. 题库已归档时，隐藏单题删除、批量删除及导入入口。
2. 归档前已打开的面板，提交时检查题库是否已归档；已归档则拒绝本次操作，提示“该题库已归档，暂不支持修改，请先恢复题库。”。
3. 恢复后，删除和导入沿用原有权限及业务规则。

这段只定义新增状态限制。完整旧删除判断不必重抄；未归档时的覆盖导入保护若是另一个改造，须单独具备范围依据。本例也不要求其他产品的归档一律禁止编辑或导入。

### 新行为依赖某项原有条件

若本次按钮互斥关系取决于“是否允许删除整个对象”，就必须核实并写清理解互斥所需的整库删除条件或精确引用。不能因为旧规则复杂就只写“符合分类”，也不能把整库删除条件用于判断单条内容能否删除。

### 实际关联影响

采用 `受影响页面/对象 → 本次变化带来的影响 → 调整后结果及范围`。例如新增字段须进入已有导出时，说明该列的位置、取值和历史记录口径即可。

关联页面没有业务变化时，不逐项声明不变。历史保留、旧入口提交及恢复后的行为，只有在本次状态变化使结果需要重新明确时写入。不要把“可能有关联”扩展成其他模块的完整需求。
