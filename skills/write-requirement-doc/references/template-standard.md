# 模板标准

## 1. 来源与使用方式

本规范参考用户提供的《需求编写模板示例V1.1_20230324.doc》。本次重构已读取原文件：`/root/zhangshijie/x-academy/docs/需求编写模板示例V1.1_20230324.doc`。以下保留可复用的结构和写法，不要求在其他环境中存在该绝对路径；用户提供新模板时以新模板为准。

原模板的通用要求：

- 完整迭代文档包含迭代周期、需求范围、需求详情；周期说明各环节日期和工作日，范围使用思维导图，技术研究以绿色星号标识。
- 每个主体需求说明背景、目标、业务流程（有流程时）和详细需求；详细需求按功能点继续拆分。
- 背景交代关键现状及问题，目标交代要达到的业务结果。
- 功能点按业务先后排列，无先后顺序时按优先级排列；功能说明前给出访问路径。
- 页面规则原则上从上到下、从左到右，先字段再提交校验；校验通常按问题严重程度编写。
- 文字、表格、原型图、流程图、状态转换图按表达需要选用。

原模板提供六类范例：字段调整、流程、多状态、列表管理、数据统计、页面展示。范例中的功能、数值和状态仅用于示范。删除量表的范例明确注明该示例页面没有此功能；编辑量表则引用新增时的约束，只单列可编辑差异。

本 Skill 的范围判断、原型核实、关联影响和交付自查是补充规范，不冒称原模板要求。字符长度、日期精度、分页条数等取项目的明确约定；原模板的例值和类型说明不自动替代项目规则。

## 2. 文档结构

完整迭代需求可按以下结构编写：

```markdown
# XX迭代需求说明书

## 1. 迭代周期说明
## 2. 需求范围
## 3. 需求详情

### 3.1 需求名称
#### 3.1.1 需求背景
#### 3.1.2 需求目标
#### 3.1.3 业务流程
#### 3.1.4 详细需求说明
##### 3.1.4.1 页面或功能点
```

适用规则：

1. 用户要求完整采用原模板时，保留所要求的章节及范围图形式。没有排期依据则说明未提供，不编造日期和工时。
2. 单项功能文档使用已约定的结构；无迭代管理信息时，不自行扩展排期和技术研究章节。没有独立流程时可省略流程小节并顺序编号，原模板的字段调整示例也采用此方式。
3. 既有文档局部修改时保留其结构，只改受影响部分；不要借修订替换整份目录。
4. 需求范围列本次要做的功能；详细说明依页面与业务顺序展开。新增和改造可以在功能标题或范围表中标注，不必将同一页面拆散到两个大章。
5. 对其他功能的影响写在对应页面；跨页面的统一规则只定义一次，相关位置写本页差异并引用。验收及待确认按实际需要放在功能末尾或独立章节，不强制添加空章。

## 3. 页面或功能点的基本写法

```markdown
### 具体页面：新增或调整的内容

功能路径：端－模块－页面

规则如下：

1. 具体位置及新增、调整的元素。
2. 该元素在实际条件下如何展示或接受输入。
3. 用户操作、系统判断及成功或拒绝后的结果。
```

这是组织顺序示例，不要求每个功能写三条。纯展示内容不补操作；后台流程写真实业务事件，不编造菜单。多字段适合表格，操作适合顺序条款，多分支适合状态或条件表；按需选用 [功能写法](writing-patterns.md)。

一个改动点应在所属页面形成完整说明：读者能确定哪里发生变化、什么条件下发生、操作后看见什么。公共业务口径可以引用，当前页面的入口和结果不应散落在多个主题章节中。

## 4. 模板逻辑的应用示例

以下仅示范组织方式，具体产品规则须来自当前任务：

- **只新增一个查询条件：** 在列表页下写查询项、选项、默认值、触发与结果范围；原有其他查询项和分页规则未变化时不重列。
- **新增完整列表管理功能：** 按页面说明字段、查询、列表、实际提供的操作及权限；模板中出现新增、编辑、删除，不代表项目必须全部提供。
- **增加某对象的归档能力：** 按筛选区、卡片操作、确认弹窗、归档后的详情变化、权限配置及直接影响展开；查看原有删除规则用于判断影响，不必在归档文档中重写删除机制。
